# 自动摘要标题

网关确认首条文字消息发送成功后，在后台生成一次简短中文标题。主聊天和侧边聊天使用同一个队列与 Codex 临时任务实现，页面读取、刷新和跨设备发现都不会触发模型请求。输入最多取首条文字的 2000 字符，不读取附件、整段历史或原聊天的项目文件。生成目标约 10–20 字，结果最多 28 字；等待或失败时显示最多 28 字的消息预览。

## 运行与保存

`bridge/features/sessions/auto_titles.py` 管理一次性任务、去重、取消和私有台账；`bridge/clients/codex/title_runtime.py` 管理原生协议。每个任务用独立 app-server 进程新建 `ephemeral: true` 会话，沿用原本的 CODEX_HOME、provider 和 model，使用低推理强度与 JSON 输出。不会 fork、resume 或向原聊天追加辅助消息。任务完成、超时、取消或出错均关闭自己的进程、清理临时目录。

标题任务关闭 shell、MCP、插件、应用、目标、技能与联网工具，项目说明读取预算为零，并使用只读策略。部分原生版本仍声明 `request_user_input`；网关拒绝此类请求及任何额外审批、工具或认证交互，并停止标题任务。用户级全局说明和运行时自己的系统上下文仍可能附加，因此输出标题字数不等于总 token 数。

主聊天通过现有 `thread/name/set` 保存原生名称；侧边聊天更新网关共享名称及递增的 `titleRevision`，沿用现有跨设备读取通道。侧边聊天自身的临时生命周期不变。

## 覆盖与重复控制

- 手动命名优先，包括把名称保存为当前文字的操作；命名会取消未完成的标题任务。写回前再核对原生名称、首条消息及当前标题，桌面端已经生成摘要时保留原生结果。原生重命名接口尚无原子条件更新，外部桌面同时改名仍存在极短竞争窗口。
- 每条聊天最多自动提交一次；台账只保存消息哈希、状态、结果及运行时报告的用量，不额外保存首条消息。运行中或结果未知的任务在重启后不自动重发。任务最多排队 32 个，同一网关一次生成一个标题。
- 任务排队期间账号或配置变化则取消；执行前再次核对配置，禁止回退到另一模型提供方。模型或运行时不兼容时保留预览，正常聊天不受影响。
- 自动摘要使用现有模型接入的额度或计费。尚未获得可靠结果的任务不自动重试；原生运行时自己的 HTTP 重试行为由该接入控制，自定义提供方在标题任务中将请求/流重试设为零。

## 本次范围与验证

本次覆盖网关电脑上的 Codex Desktop 主聊天及侧边聊天的新首条文字消息。CLI、SSH 聊天保留原生标题行为；已有历史聊天不会在读取时批量补生成或改名。首条仅有附件而无文字时不生成摘要。

回归入口：`python -B scripts/test-backend.py --source-only -p test_auto_titles.py`、`test_session_titles.py`、`test_side_chat.py`，以及 `npm run test:desktop`。`python -B scripts/smoke-auto-title.py` 使用真实 Codex 运行时和本地模拟模型，验证实际请求、隐藏历史、工具限制、用量与进程/目录清理，不使用真实账号。
