# 自动摘要标题

## 聊天菜单中的显式改名

Codex 和 DeepSeek 的左侧聊天列表菜单均提供“AI重命名”和“重命名”：电脑右键、手机和平板长按打开。手工改名可以直接操作未打开的聊天，输入 1–120 字后保存到原生客户端。

“AI重命名”在点击后立即提交独立标题任务，读取当前聊天的用户和助手文字，生成约 10–20 字、最多 28 字的中文标题并自动保存。已有手工或 AI 标题也可再次显式生成。长会话对输入进行有界截取，兼顾前段主题和最新讨论；排除工具输出、思考、附件与项目文件，不向原聊天发送消息。窗口显示排队、生成、完成或结果未知，关闭窗口后任务可在后台完成。

Codex 使用原聊天的模型/provider 与隔离 ephemeral app-server；只在用户点击后读取最近 100 轮保存记录，并结合已取得的实时文字，提供给模型的正文最多约 12000 字符。此入口目前支持本机 Desktop 来源，CLI 和 SSH 的 AI 入口保持禁用，手工改名沿用各来源原有能力。接口为 `GET/POST /api/sessions/<id>/ai-rename`，POST 仅接受 UUID `id`。首条消息的自动标题规则与下面的旧补生成入口继续独立工作。

DeepSeek 复用当前 Host 的 `llm.prepareCall` 和标题队列，工具列表为空，不创建、恢复或执行原聊天 agent。通过 `manage` 的 `ai-rename` 操作提交 UUID，通过只读 `title-status` 查询；需要接入协议第 8 版，旧版第 7 版已加入来源指纹与生命周期兼容清单，更新沿用现有“重启并接入”流程。源码开发和回归不自动更新或重启真实客户端。

两者均保留原模型接入的额度/计费。相同请求 ID 和生成中的重复点击不会多次调用，合并的请求 ID 也持久保存关联；未知结果及网关/Host 重启后的遗留任务不会自动重发。状态查询带上本次 `requestId`，未找到任务时返回未知，不借用旧任务的成功结果。手工改名（包括保存原名）优先，写回前再次检查标题及接入，外部改名或归档时放弃旧结果。任务台账不另存对话正文。

验证入口：`python -B scripts/test-backend.py --source-only -p test_title_rename.py`、`node --test tests/deepseek-personal.test.mjs`、`node scripts/test-chat-rename-browser.cjs`。完整生产页面的隔离 Chromium 回归覆盖 320、390、820、1280 像素、两个客户端、右键/长按、未打开聊天的改名、丢失回执与未知结果，不连接真实客户端或模型。

如果已经看到新菜单，但提示“页面不存在”，应检查电脑端网关是否仍是更新源码前启动的进程。Web 资源可以即时读取磁盘新文件，Python 接口和业务代码则由运行中的进程保留；仅刷新网页不能加载新接口。窗口现在先只读检查接口，遇到明确的接口缺失会提示更新或重启网关，并停止提交及轮询；真实会话不存在仍保留原错误。重启前需检查网关内的临时侧边聊天和终端，因为网关关闭流程会结束它们，不能在仍有任务时静默重启。

`node scripts/test-chat-rename-browser.cjs --unavailable-only` 单独验证旧网关检查、提交及查询阶段的 404、会话不存在，以及检查期间关闭窗口后不继续提交。它使用合成接口，不重启真实服务。

## 首条消息自动标题

网关确认首条文字消息发送成功后，在后台生成一次简短中文标题。主聊天和侧边聊天使用同一个队列与 Codex 临时任务实现，页面读取、刷新和跨设备发现都不会触发模型请求。输入最多取首条文字的 2000 字符，不读取附件、整段历史或原聊天的项目文件。生成目标约 10–20 字，结果最多 28 字；等待或失败时显示最多 28 字的消息预览。

## 运行与保存

`bridge/features/sessions/auto_titles.py` 管理一次性任务、去重、取消和私有台账；`bridge/clients/codex/title_runtime.py` 管理原生协议。每个任务用独立 app-server 进程新建 `ephemeral: true` 会话，沿用原本的 CODEX_HOME、provider 和 model，使用低推理强度与 JSON 输出。不会 fork、resume 或向原聊天追加辅助消息。任务完成、超时、取消或出错均关闭自己的进程、清理临时目录。

标题任务关闭 shell、MCP、插件、应用、目标、技能与联网工具，项目说明读取预算为零，并使用只读策略。部分原生版本仍声明 `request_user_input`；网关拒绝此类请求及任何额外审批、工具或认证交互，并停止标题任务。用户级全局说明和运行时自己的系统上下文仍可能附加，因此输出标题字数不等于总 token 数。

主聊天通过现有 `thread/name/set` 保存原生名称；侧边聊天更新网关共享名称及递增的 `titleRevision`，沿用现有跨设备读取通道。侧边聊天自身的临时生命周期不变。

## 覆盖与重复控制

- 手动命名优先，包括把名称保存为当前文字的操作；命名会取消未完成的标题任务。写回前再核对原生名称、首条消息及当前标题，桌面端已经生成摘要时保留原生结果。原生重命名接口尚无原子条件更新，外部桌面同时改名仍存在极短竞争窗口。
- 每条聊天最多自动提交一次；台账只保存消息哈希、状态、结果及运行时报告的用量，不额外保存首条消息。运行中或结果未知的任务在重启后不自动重发。任务最多排队 32 个，同一网关一次生成一个标题。
- 任务排队期间账号或配置变化则取消；执行前再次核对配置，禁止回退到另一模型提供方。模型或运行时不兼容时保留预览，正常聊天不受影响。
- 自动摘要使用现有模型接入的额度或计费。尚未获得可靠结果的任务不自动重试；原生运行时自己的 HTTP 重试行为由该接入控制，自定义提供方在标题任务中将请求/流重试设为零。

## 本次范围与验证

本次覆盖网关电脑上的 Codex Desktop 主聊天及侧边聊天的新首条文字消息。CLI、SSH 聊天保留原生标题行为；首条仅有附件而无文字时不生成摘要。

历史聊天不会在读取时批量补生成或改名。由本网关创建、当时选择自动标题、仍显示首条消息预览且没有标题任务记录的本机 Desktop 聊天，会在下一次普通发送成功后补生成一次，输入仍取数据库保存的原始首条文字，不取后续消息或分页历史。队列满而尚未提交的任务也可沿此路径补上；已有任务记录（包括结果未知）不自动重试。

本机 Desktop 聊天的“修改聊天名称”窗口提供“生成简短名称”，可显式补生成已有聊天的预览标题。`GET /api/sessions/<id>/auto-title` 只读资格、状态与当前展示名称；`POST` 同一路径仅接受空对象，使用登录和 CSRF 校验，并复用一次性任务台账。它只从数据库及已取得的实时快照读取首条消息、模型与 provider，不读取聊天历史或激活原会话。缺少模型接入时提示先连接，不回退到全局模型。完成后通过原生名称写回，桌面和手机共同读取；已有原生名称、手动选择、归档和不支持的来源不能启动新摘要。

生成窗口显示排队、运行、完成或结果未知；丢失提交回执只查询状态，不重复 POST。关闭或切换窗口后丢弃旧查询，生成期间用户手填的名称不会被回包覆盖。手动保存仍可取消后台摘要。输入与摘要沿用原模型接入的额度或计费。
