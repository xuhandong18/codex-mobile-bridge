# Android 通知与输入草稿

Android 的任务通知标题以会话名称开头，结尾固定为 `· 已完成` 或 `· 待确认`。长名称在状态前使用省略号，为完整状态预留空间；按中英文字符的显示宽度限制整行长度。通知正文仍可展开查看，应用来源显示为 Codex、Claude 或 DeepSeek Harness。

本机通知和可选 FCM 推送共用收件箱中的 `androidTitle`。这是 Android 的专用显示字段；其他平台及第三方通知仍沿用原有标题显示设置。旧网关事件没有该字段时，Android 回退到原来的 `title`。

点击同一台已保存电脑的通知时，在当前 WebView 内切换会话。当前会话已经打开时保持输入框和阅读位置。打开其他电脑或冷启动时仍建立该电脑的页面，不转移登录凭据。链接必须指向已保存电脑，并保留会话标识、宿主和来源校验。

应用列表尚在读取时保留待打开的通知，待完整结果返回再定位客户端。新通知替换待处理的旧通知，用户主动切换应用会取消待处理的跳转。完整状态明确显示应用已停用时，仍提示打开应用管理；通知不自动启用或启动客户端。

页面加载和重新注入脚本会再次保存登录状态。同一个已验证登录的重复保存只刷新通知检查，不重置已建立的事件基线；否则新事件会进入收件箱，却被误当作历史而跳过系统通知。基线同时绑定电脑地址、当前登录和事件流；换登录、真正从后台返回或事件流重置时仍重新建立基线，不集中弹出历史提醒。

Codex、Claude 和 DeepSeek 的普通聊天输入文字在编辑时保存到本机 localStorage，按网关路径、已认证登录身份、客户端和会话隔离；Codex 还区分本机与 SSH 宿主。页面或 WebView 重建后，在相同有效登录身份下恢复。会话列表提供的 `listCacheIdentity` 只用于存储分区，不授予登录权限。认证失效时隐藏旧分区；重新认证产生不同身份时不显示旧身份的文字。主动退出登录会清除当前身份的草稿。

只有发送结果确认、且草稿仍与发送内容相同时才清除文字；结果未知和发送失败时保留草稿，不自动发送或重发。这个持久化范围是普通输入文字；附件、引用卡片和交互问题答案继续由各自模块管理。

验证入口见 [tests/README.md](../tests/README.md)。重复登录保存的缺陷已用旧 APK 在隔离 Android 35 模拟器复现；修复 APK 通过真实 WebView、系统通知、标题、重复保存、已读过滤和换登录基线的 9 项检查。模拟器验证不代表物理手机和各厂商通知横幅均已验证。
